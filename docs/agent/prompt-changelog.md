## 1. 프롬프트 정의 (현재)

### 1.1 역할 (페르소나)

"사출성형 라인의 품질 엔지니어를 돕는 원인 분석 에이전트". 임무는 근거를 모아 원인을 추정하고 처리 방향을 **제안**하는 것이고, "최종 결정은 사람이 하며 결과는 검토용 초안"임을 첫 문단에 밝힙니다.

### 1.2 구성

| 절 | 역할 | 종류 |
|---|---|---|
| [조사 절차] | 결론 전에 도구로 근거 확인. 1 센서 전체 비교 → 2 추이(넓게·좁게) → 3 불량 → 4 과거 사례 → 5 정비 이력 → 6 SOP | 사고 과정 유도 (CoT 대신 **도구 순서**로 유도) |
| [경보 규칙의 의미] | INDIVIDUAL·XBAR·S_CHART·P_CHART 의 뜻. "지속성 경보를 단발성으로 판단하지 말 것" | 도메인 지식 |
| [판단 기준] | NCR_DRAFT / SENSOR_CHECK / OBSERVE 조건 | 출력 정책 |
| [확신도 기준] | 80 이상 / 50~79 / 50 미만의 근거 조건 | 보정 |
| [이전 판단]·[재확인]·[검토자 메모] | 기억을 어떻게 쓸지 ([메모리 설계서](memory-architecture.md)) | 기억 사용 규칙 |
| [원인 코드] | 7개 코드 목록 | 출력 어휘 |
| [작성 규칙] | 근거에 실제 수치, 결과에 있는 번호만 인용, 한국어 | **가드레일** |
| [출력 형식] | JSON 하나만, 키 12개 | 형식 계약 |

### 1.3 행동 제약 (가드레일 문장)

| 제약 | 문장 요지 | 코드로도 막는가 |
|---|---|---|
| 결론 전 근거 확인 | "결론을 내기 전에 반드시 도구로 근거를 확인" | 검증 에이전트: 추이·불량을 조회하지 않고 낸 결론은 되돌림 |
| 수치 지어내기 금지 | "수치는 도구 결과의 값을 그대로 옮긴다. 검증 에이전트가 대조한다" | 규칙 6 수치 대조 |
| 사례 번호 지어내기 금지 | "findSimilarNcr 결과에 실제로 있는 번호만" | 검증 에이전트: 기준 시점까지 승인된 사례에 없으면 되돌림 |
| SOP 번호 지어내기 금지 | "결과에 없는 문서 번호는 지어내지 마세요" | — (프롬프트만) |
| 메모 맹신 금지 | "메모만으로 결론을 정하지 말고, 데이터가 다르면 데이터를 따르라" | — (프롬프트만) |
| 사람 결정 | "최종 결정은 사람" | 승인 화면 (H-01) |

### 1.4 일부러 넣지 않은 것

- **원인-센서 대응표**(예: "실린더 온도 하락이면 히터"): 처음 보는 고장에서 무너지므로, 과거 사례를 도구로 찾아 추론하게 했습니다(`AgentPrompts` 주석, 개발 원칙 "특정 고장 맞춤 힌트 금지").
- **자유 형식 사고 과정 출력**: 판단 이유는 `reasoningSummary` 한 칸에 요약만 받습니다. 긴 사고 과정은 토큰만 늘고 검증할 수 없기 때문입니다.

### 2.1 지금 알아 둘 점

- **마지막 측정(5/5, 47.3초)은 현재 버전(d54b8a16)보다 앞선 프롬프트로 냈습니다.** 그 뒤 출력 키(candidateCauses)와 조사 절차 6단계가 더해졌으므로, 현재 main 재평가(로드맵 E3) 전에는 "현재 버전의 정확도"로 말할 수 없습니다.
- 파일 이름은 `analysis-v1` 그대로이고 해시만 바뀌었습니다. 앞으로 **판단 기준·조사 절차처럼 결과에 영향을 줄 변경은 `analysis-v2.md` 로 새 파일**을 만들고, 이 표에 한 줄을 더한 뒤 재평가합니다.
- 도구 설명(`@Tool` description)도 모델 입력이므로 바꾸면 이 표에 적습니다. 다만 해시에는 들어가지 않습니다.

## 3. 변경 절차

1. 바꿀 이유를 실패 사례나 지표로 적는다 (예: "히터 열화 0/3, 지속성 경보를 단발성으로 판단").
2. 특정 고장 맞춤 문장이 아닌지 확인한다.
3. 새 파일(`analysis-vN.md`)을 만들고 `AgentPrompts.ANALYSIS_FILE` 을 바꾼다. 형식만 바꾸면 같은 파일을 고쳐도 된다.
4. `scripts/evaluate_agent.py` 로 같은 정답 데이터에서 재평가하고 `scripts/ab_compare.py <이전 결과> <새 결과>` 로 비교한다. 결과 폴더의 `meta.json` 에 프롬프트 버전이 남는다.
5. 이 표에 날짜·버전·이유·평가를 적는다.
