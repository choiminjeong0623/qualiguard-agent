# 01. 문제 정의

## 1. 배경

사출성형처럼 같은 동작을 수천 번 반복하는 공정에서는 설비 상태가 **갑자기가 아니라 서서히** 나빠지는 경우가 많습니다. 히터가 조금씩 약해지거나, 금형 냉각수 유로가 조금씩 막히거나, 부품이 조금씩 마모됩니다. 이런 변화는 처음에는 센서 값이 정상 범위 안에서 살짝 움직이는 정도라 눈에 띄지 않고, **불량이 눈에 보일 만큼 늘어난 뒤에야** 알아채게 됩니다.

불량을 발견한 뒤에도 일이 남습니다. 품질 담당자는 원인을 찾기 위해 여러 곳을 오가며 자료를 모으고, 부적합 보고서를 작성해야 합니다.

## 2. 사용자

| 사용자 | 하는 일 | 겪는 어려움 |
|---|---|---|
| **품질 담당자** (주 사용자) | 불량 발생 시 원인 분석, 부적합(NCR) 보고서 작성, 시정조치 관리 | 센서 그래프·검사 결과·과거 부적합 이력·정비 기록이 각각 다른 시스템에 있어 자료를 모으는 데 시간이 많이 듦. 보고서 품질이 담당자 경험에 따라 달라짐 |
| 설비 담당자 | 설비 점검·정비 | 품질 문제가 설비 원인인지 늦게 전달받음 |
| 생산 관리자 | 라인 가동·불량률 관리 | 불량이 쌓인 뒤에야 보고를 받음 |

## 3. 현재 업무 흐름과 문제점

```
불량 증가를 인지 → 센서 데이터 조회 → 검사 결과 조회 → 과거 유사 부적합 검색
→ 정비 이력 확인 → 원인 추정 → 부적합 보고서 작성 → 승인 → 관련 부서 전달
```

| 문제 | 영향 |
|---|---|
| **늦은 인지**: 불량이 늘어난 뒤에야 이상을 앎 | 그사이 불량품이 계속 생산됨 |
| **흩어진 자료**: 원인 분석에 필요한 데이터가 여러 시스템에 분산 | 분석과 보고서 작성에 시간이 많이 듦 |
| **경험 의존**: 원인 추정이 담당자의 경험에 크게 의존 | 담당자마다 분석 품질이 다르고, 과거 사례가 재활용되지 않음 |
| **수작업 연계**: 승인 결과를 다른 시스템에 다시 입력 | 누락·지연 위험 |

## 4. 목표

1. **조기 감지**: 불량이 늘어나기 전에, 센서 값이 서서히 움직이는 단계에서 이상을 감지한다.
2. **근거 수집 자동화**: 이상이 감지되면 원인 분석에 필요한 자료(센서 추이, 규격, 유사 사례, 정비 이력)를 자동으로 모은다.
3. **보고서 초안 자동 작성**: AI가 근거를 달아 원인을 추정하고 부적합 보고서 초안을 작성한다.
4. **사람의 최종 판단 유지**: 확정은 품질 담당자가 한다. AI는 초안과 근거를 제공할 뿐 스스로 확정하지 않는다.
5. **시스템 간 자동 연계**: 승인 결과를 MES/ERP 등으로 자동 전달한다.

## 5. 범위

| 포함 | 제외 |
|---|---|
| 사출성형기 2대, 센서 7종, 인라인 비전 검사 결과 | 실제 설비·PLC 연동 (시뮬레이터로 대체) |
| SPC 관리도 기반 이상 탐지 | 설비 제어(자동 정지 등) |
| 원인 추정·부적합 보고서 초안 | 시정조치의 실행·효과 검증 관리 전체 |
| QMS 승인 화면, MES/ERP 연계 이벤트 | 실제 MES/ERP 시스템 (가상 수신 서비스로 대체) |

## 7. 성공 지표

| 지표 | 목표 | 현재 |
|---|---|---|
| 실제 고장 감지율 | 시나리오 3종 모두 감지 | ✅ 3/3 |
| 감지 시점 | 첫 불량 발생 전 | ✅ 3/3 |
| 정상 구간 오경보 | 설비당 수 건 이하 | ✅ 2건 / 정상 2,200 shot |
| 원인 추정 정확도 | 고장 4종 중 4종 | ✅ 4/4 (시간 순 재생 평가 3회 반복 12/12) |
| 오경보 판별 | 단발성 경보를 "관찰"로 분류 | ✅ 3/3 (3회 반복) |
| 에이전트 진단 시점 | 첫 불량 전 (고장 구간 기준) | ❌ 3/4 — 냉각 막힘·센서 이상은 첫 불량 전, 체크 링 마모는 2/3회 전·1회 같은 shot, **히터 열화는 +96 shot으로 첫 불량(+68) 뒤** |
| 보고서 초안 생성 시간 | 분석 1단계 1분 이내 | ❌ 미달 — 29~65초, 한 번 114초 (과거 사례 숨김 실험 35~108초) |

측정 방법과 상세 결과는 [평가 결과](evaluation.md)에 있습니다. 에이전트 지표는 경보를 발생 순서대로, 그 시점까지의 데이터만으로 판단하는 시간 순 재생 평가 기준입니다 ([장애 분석 04](troubleshooting/04-agent-evaluation-leakage.md)).
