# ADR-001. MQTT 메시지를 shot 단위로 묶는다

- 상태: 채택
- 날짜: 2026-11-14

## 배경
처음 설계에서는 MQTT 토픽을 `factory/{라인}/{설비}/{센서}`처럼 **센서별로** 나눠, 센서마다 값을 따로 보내려 했습니다.

## 고려한 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 센서별 토픽, 값 1개씩 | 센서를 추가하기 쉬움, 필요한 센서만 구독 가능 | 같은 shot의 값들이 따로 도착해 다시 맞춰야 함. 일부만 도착하면 판단이 어려움 |
| **B. 설비별 토픽, shot 1건에 모든 센서** | 같은 shot의 값이 항상 함께 있음. 검사 결과(OK/NG)와 공정 값을 바로 연결 가능 | 메시지가 조금 큼, 센서별 구독 불가 |

## 결정
**B**를 택했습니다. 토픽은 `factory/{라인}/{설비}/telemetry`, 메시지 1건 = shot 1회입니다.

## 근거
- 실제 사출성형기도 사이클(shot) 단위로 공정 데이터를 보고합니다(Euromap 63/77 등).
- 원인 분석은 "같은 shot에서 온도는 내려가고 압력은 올라갔다"처럼 **센서들을 함께 봐야** 합니다. 센서별로 흩어 보내면 수신 측에서 다시 묶는 일이 생기고, 일부만 도착한 경우의 처리가 복잡해집니다.
- 비전 검사 결과(불량 여부·유형)를 같은 메시지에 넣어야 "어떤 공정 조건에서 불량이 났는지"를 바로 알 수 있습니다.

## 결과
- 메시지마다 `messageId`를 붙여 중복 제거의 기준으로 씁니다.
- Kafka 메시지 key를 설비 ID로 두어, 같은 설비의 shot은 순서대로 처리됩니다.
