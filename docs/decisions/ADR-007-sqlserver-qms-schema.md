# ADR-007. QMS 데이터는 shot 원본으로 저장하고, 조회는 저장 프로시저로 제공한다

- 상태: 채택
- 날짜: 2026-11-14

## 배경
에이전트가 원인을 추정하고 QMS 화면이 목록을 보여 주려면 공정 데이터, 이상 이력, 검사 규격, 정비 이력, 과거 부적합 사례가 DB에 있어야 합니다. 정해야 할 것은 세 가지였습니다.
1. 공정 데이터를 어떤 단위로 저장할지
2. 에이전트·화면이 데이터를 어떻게 조회할지
3. 지난 경보를 나중에 분석할 때 어느 시점의 데이터를 보여 줄지

## 결정 1. shot 원본을 저장하고, 집계는 조회할 때 계산한다
| 선택지 | 장단점 |
|---|---|
| 1분 단위 집계만 저장 | 저장량이 적지만, 나중에 다른 기준(구간 크기, 불량 유형별)으로 다시 볼 수 없음 |
| **shot 원본 저장 (`process_shot`)** | 저장량이 많지만 어떤 기준으로든 다시 집계 가능. 실제 30초/shot 기준 설비당 하루 2,880건 수준이라 부담이 작음 |

시뮬레이터는 실제보다 훨씬 빠르게 데이터를 보내므로, 조회 범위는 시간 대신 **"최근 N shot"**으로 잡았습니다.

## 결정 2. 조회는 저장 프로시저로 제공하고, 에이전트는 이를 도구로 쓴다
| 프로시저 | 용도 |
|---|---|
| `usp_GetSensorTrend` | 센서 추이 (구간별 평균·최소·최대·표준편차·불량 수 + 규격) |
| `usp_GetSpcSummary` | 센서별 공정 능력 지수(Cpk), 규격 이탈 수 |
| `usp_GetDefectSummary` | 구간별 불량률, 불량 유형별 건수 |
| `usp_FindSimilarNcr` | 유사 과거 부적합 사례 (지식저장소) |
| `usp_GetMaintenanceHistory` | 정비 이력 |
| `usp_ListAnomalies` | 이상 이력 목록 |

- 에이전트가 SQL을 직접 만들지 않고 **정해진 프로시저만 호출**하므로, 잘못된 쿼리나 과도한 조회를 막을 수 있습니다.
- 같은 프로시저를 QMS 화면에서도 쓸 수 있습니다.
- 채용 공고의 필수 요건(MS SQL 쿼리·프로시저)을 실제 쓰임새가 있는 형태로 보여 줍니다.

## 결정 3. 규격 한계와 관리 한계를 구분한다
| 구분 | 의미 | 출처 | 저장 위치 |
|---|---|---|---|
| **규격 한계 (LSL/USL)** | 제품이 합격하려면 지켜야 하는 범위 | 설계·고객 | `sensor_spec` |
| **관리 한계 (μ±kσ)** | 공정이 평소처럼 돌고 있는지 보는 범위 | 데이터에서 계산 | 이상 탐지 엔진 |

두 값을 함께 보면 "평소와 다르지만 아직 규격 안"(조기 경보)과 "규격 이탈"(불량 위험)을 구분할 수 있습니다. `usp_GetSpcSummary`의 **Cpk**는 둘을 하나의 숫자로 보여 줍니다 (1.33 이상 양호, 1.0 미만 부족).

## 결정 4. 지난 경보는 "경보 당시까지의 데이터"로만 분석한다 (`@AsOf`)
**발견한 문제.** 처음 설계에서는 조회가 "최근 N shot"이었습니다. 그런데 DB에는 시뮬레이션이 끝난 시점까지 데이터가 다 있어서, 300번째 shot의 경보를 나중에 분석하면 **2,000번째 shot 무렵의 데이터**를 보게 됩니다. 평가 결과를 믿을 수 없게 만드는 문제입니다(미래 데이터가 섞이는 누수).

**조치.** 추이·공정 능력·불량 요약 프로시저에 `@AsOf`(기준 시점)를 추가했습니다. 에이전트 도구는 **사건의 마지막 경보 시각**을 기준 시점으로 고정해 호출하며, 이 값은 모델이 바꿀 수 없도록 도구 인자로 노출하지 않습니다.

## 결과
- 초기화 스크립트(`infra/mssql/init/02~05`)는 여러 번 실행해도 안전하게 작성했습니다 (없을 때만 생성, `CREATE OR ALTER`, `MERGE`).
- 중복 방어를 DB에서 마무리했습니다. `INSERT ... WHERE NOT EXISTS`와 고유 인덱스(`message_id`, `anomaly_id`)를 쓰고, Kafka Streams 트랜잭션에 맞춰 적재 소비자는 `read_committed`로 읽습니다.
- 과거 부적합 사례 5건 중 1건(원료 건조 불량으로 인한 미성형)은 **헷갈리게 하는 사례**로 넣었습니다. 불량 유형만 보고 판단하는지 시험하기 위해서입니다.
