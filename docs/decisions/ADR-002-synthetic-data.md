# ADR-002. 합성 데이터를 주력으로, 공개 데이터는 보조로 쓴다

- 상태: 채택
- 날짜: 2026-11-14

## 배경
포트폴리오에서 실제 공장 데이터를 쓸 수 없으므로 데이터를 정해야 했습니다.

## 고려한 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| UCI SECOM (실제 반도체 공정) | 실제 데이터라 신뢰도가 높음, 가입 없이 사용 | 센서 590여 개가 **이름 없이 번호로만** 되어 있어 원인을 설명할 수 없음 |
| KAMP 제조 데이터셋 (국내 실제 공정) | 센서 이름이 있음 | 회원가입·데이터셋별 이용 조건 확인 필요, 고장 시점 정답이 없을 수 있음 |
| **합성 데이터 + 고장 시나리오** | 센서 의미가 분명함, 고장을 원하는 시점에 주입 가능, **정답을 기록**할 수 있음 | 실제 데이터가 아님 |

## 결정
**사출성형 라인 합성 데이터를 주력**으로 쓰고, SECOM은 이상 탐지 모델을 실제 데이터로도 검증하는 **보조 실험**에 씁니다.

## 근거
- 이 프로젝트의 핵심은 LLM이 "실린더 온도가 떨어지고 사출 압력이 오른다 → 히터 열화 가능성"처럼 **원인을 설명**하는 것입니다. 센서가 번호로만 되어 있으면 LLM이 할 수 있는 일이 없습니다. AI가 잘할 수 있는 조건을 먼저 만드는 것이 우선이라고 판단했습니다.
- 시뮬레이터가 "언제 어떤 고장이 진행 중이었는지"를 정답으로 남기면, 탐지 지연·오경보·원인 추정 정확도를 **숫자로 평가**할 수 있습니다.
- 고장마다 센서 반응이 다르게 설계했습니다(히터 열화: 온도↓ 압력↑ / 체크 링 마모: 쿠션량↓ 압력 변동↑). 같은 미성형 불량이라도 원인을 구분해야 하는 시험이 됩니다.

## 결과
- 고장 시나리오 4종: 히터 열화, 금형 냉각 막힘, 체크 링 마모, 압력 센서 이상(품질 영향 없음 — 오탐 판별 시험용)
- seed 고정으로 같은 데이터를 재현해 데모와 평가에 씁니다.
- README와 평가 문서에 **합성 데이터이며 성과는 시뮬레이션 수치**임을 명시합니다.
