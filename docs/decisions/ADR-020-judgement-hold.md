# ADR-020. 판단 보류: 에이전트가 결론을 내지 못하면 사람 검토로 넘긴다

- 상태: 채택
- 날짜: 2026-11-23
- 관련: [ADR-016](ADR-016-multi-agent-pipeline.md) (검증 에이전트), 로드맵 F2

## 배경
관찰(OBSERVE) 판단 뒤에는 새 경보가 없어도 `recheck-shots` 마다 다시 분석하고, 상한(`recheck-max`, 기본 3회)까지 반복한다.
상한에 닿으면 스케줄러는 더 재확인하지 않는다. 그 마지막 분석도 OBSERVE 이면 경보는 이미 DISMISSED 이고,
**원인을 정하지 못한 사건이 누구에게도 보이지 않은 채 끝난다.**

검증 에이전트도 같은 빈틈이 있었다. 재분석 뒤에도 지적이 남으면(WEAK) 결과를 그대로 저장하는데,
결론이 부적합 초안이면 어차피 검토자가 보지만, 관찰·센서 점검이면 경보가 근거 부족한 채로 종결된다.

## 고려한 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 상한을 없애고 계속 재확인 | 단순 | LLM 비용이 끝없이 늘고, 같은 데이터로 같은 결론을 반복할 가능성이 큼 |
| B. 상한에서 강제로 부적합 초안 생성 | 사람에게 보임 | 근거 없는 부적합이 쌓여 검토자 신뢰가 떨어지고, 원인 코드가 UNKNOWN 인 초안이 지식 베이스에 섞임 |
| **C. 판단 보류로 표시하고 사람 검토 목록에 올림** | 자동화의 한계를 숨기지 않음. 부적합·지식 베이스를 오염시키지 않음 | 검토자가 볼 목록이 하나 늘어남 |

## 결정: C
`JudgementHoldPolicy`(순수 함수)가 분석 저장 직후 보류 여부를 정한다.

| 사유 | 조건 | 왜 |
|---|---|---|
| `RECHECK_LIMIT` | 재확인(RECHECK) + OBSERVE + 재확인 횟수 ≥ `recheck-max` (상한이 0 이면 쓰지 않음) | 자동화가 더 할 일이 없음 |
| `VERIFY_WEAK` | 검증 WEAK + 결론이 부적합 초안이 아님 | 근거 부족한 경보 종결 |

- 보류된 분석은 `agent_analysis.hold_status = 'PENDING'` 과 사유·설명을 남긴다 (`19_judgement_hold.sql`).
- QMS "에이전트 조치" 화면 아래 **판단 보류 · 사람 검토 필요** 카드에 보이고, 검토자(REVIEWER)가 처리 메모를 적어 닫는다(`RESOLVED`, 처리자·시각 기록).
- 평가 실행(run_tag 있음) 기록도 보류를 표시하지만, 화면 목록은 기본으로 운영 기록만 보여 준다(`replay=true` 로 포함).

## 결과
- 원인 미확정 사건이 "조용한 종결" 대신 사람에게 보인다. 보류 건수는 자동화 범위를 재는 지표로도 쓸 수 있다
  (보류율이 높으면 프롬프트·도구·재확인 간격을 다시 봐야 한다는 신호).
- 남은 일: 보류율을 평가 리포트에 넣는 것.

## 후속 (2026-11-23): 검토자 보조
"보류 여부도 LLM 에이전트가 정하면 어떨까"를 검토했고, **정하는 것은 규칙으로 둔다.**
판단 보류는 LLM 이 결론을 못 냈을 때의 안전장치라, 여기까지 LLM 에 맡기면 "그 LLM 이 틀리면 누가 잡나"가 다시 생긴다.
조건이 숫자·상태로 정확하고(`if` 한 줄), 단위 시험으로 모든 경우를 확인할 수 있다는 점도 규칙이 낫다.

대신 LLM 은 **검토자를 돕는 일**에만 쓴다.
- **보류 요약** (`HoldBriefService`, `POST /api/qms/holds/{id}/brief`, `20_hold_brief.sql`): 보류 건과 그 앞 분석들(parent_analysis_id)을
  읽고 3줄 요약 + 현장 확인 항목(최대 3개)을 `hold_brief` 에 저장한다. 도구 없이 저장된 기록만 읽고, 판단·원인 코드를 새로 내지 않는다.
  LLM 이 없거나 실패하면 기록에서 바로 뽑은 요약(`source: RULE`)으로 대신한다. 검토자가 화면에서 눌렀을 때만 만든다(비용).
- **검토자 메모 전달**: 처리(RESOLVED) 메모를 같은 설비의 다음 분석 입력 `reviewerNotes` 로 넘긴다(최근 3건, 분석 기준 시각 전에
  처리된 것만, 처리자 이름 제외). 프롬프트는 "메모만으로 결론을 정하지 말고 지금 데이터를 따르라"고 지시한다.
  평가 실행(run_tag 있음)에는 넣지 않아 사람 메모가 채점에 섞이지 않는다.
