# ADR-014. 유사 사례 의미 검색: SQL Server 2025 VECTOR + Gemini 임베딩, 키워드 점수에 더하는 방식

- 상태: 채택
- 날짜: 2026-11-15
- 관련: [ADR-008](ADR-008-agent-design.md) "다음에 검토할 것"(벡터 검색), F-10(지식저장소), [ADR-007](ADR-007-sqlserver-qms-schema.md)(조회는 저장 프로시저)

## 배경
`findSimilarNcr`는 관련 센서·불량 유형·설비가 겹치는 정도로만 점수를 매깁니다. 승인된 AI 초안이 지식저장소에 쌓이면(F-10) 같은 현상을 다른 말로 쓴 사례가 늘어나는데, 센서 키가 조금만 달라도 찾지 못합니다.

## 결정 1. 벡터는 SQL Server 2025 의 `VECTOR` 형식에 둔다
로컬 SQL Server 2025(CU11)에서 `VECTOR(n)`과 `VECTOR_DISTANCE('cosine', …)`가 동작하는 것을 확인했습니다.

| 선택지 | 장단점 |
|---|---|
| 별도 벡터 DB (pgvector, Qdrant 등) | 기능은 많지만 8GB 환경에 서버가 하나 더 늘고, 기준 시점·상태 조건을 두 저장소에 나눠 걸어야 함 |
| **SQL Server `VECTOR`** | 지식저장소(`ncr`)와 같은 DB, 같은 프로시저 안에서 **상태(APPROVED·CLOSED)·기준 시점(@AsOf) 조건과 함께** 검색 |

`ncr_embedding(ncr_id, embedding VECTOR(768), model, text_hash)`. 사례 수가 적어 벡터 인덱스 없이 전부 비교합니다.

## 결정 2. 키워드 점수를 대체하지 않고 더한다
`usp_FindSimilarNcr`에 `@QueryVector`(현재 현상 설명의 임베딩)를 받으면:
- 점수 = 기존(센서 일치 × 2 + 불량 유형 × 2 + 같은 설비) + 의미 유사도가 0.6 을 넘는 만큼(× 10, 반올림)
- 의미 유사도 0.75 이상이면 센서·불량 유형이 안 맞아도 후보에 넣음
- 결과에 `semantic_similarity` 열

벡터만으로 고르면 문장이 비슷한 엉뚱한 사례(예: 불량 유형만 같은 원료 사례)가 올라올 수 있어, **센서 패턴 일치를 기본으로 두고 의미 유사도는 보탬**으로 썼습니다. 기준 시점 조건은 그대로라 미래에 승인된 사례는 벡터로도 보이지 않습니다.

## 결정 3. 임베딩은 Gemini `gemini-embedding-001`(768차원), 만드는 시점은 승인과 분리
- 지식저장소 사례의 글(제목·현상·확정 원인·근거)을 1분마다 확인해 **벡터가 없거나 내용(해시)이 바뀐 것만** 만듭니다. 승인 트랜잭션에 외부 API 호출을 넣지 않기 위함입니다.
- 에이전트는 `findSimilarNcr`의 `situation`(지금 관찰한 현상 요약, 선택)을 채우면 같은 모델로 임베딩해 검색합니다. 같은 설명은 캐시합니다.
- 임베딩이 꺼져 있거나(`qg.knowledge.vector-enabled=false`) 실패하면 **키워드 검색만** 하고 분석은 계속합니다.

## 결과
- MCP 도구(ADR-013)의 `findSimilarNcr`도 같은 `situation`을 받습니다.
- 도구 호출 기록에는 설명 문장만 남기고 벡터 값은 남기지 않습니다.

## 한계
- 지식저장소가 작아(사람 작성 5건 + 승인한 AI 초안 몇 건) 의미 검색의 효과를 수치로 보이기 어렵습니다. 재생 평가로 **정확도가 떨어지지 않는지**만 확인합니다.
- 임베딩 모델을 바꾸면 모든 벡터를 다시 만들어야 합니다(`model` 열로 구분).
