# ADR-012. MES/ERP 응답: 단계 번호로 순서를 지키고, 응답 ID 로 중복을 거르고, 실패한 시스템에만 다시 보낸다

- 상태: 채택 (현재 구현). 전송 수단을 인터페이스(EAI) 서버로 바꾸는 계획은 [ADR-018](ADR-018-mes-erp-eai-interface-server.md)
- 날짜: 2026-11-15
- 관련: F-09, [ADR-010](ADR-010-ncr-integration-outbox.md)(아웃박스 연계)의 한계 "응답을 되받는 흐름 없음"을 해소

## 배경
ADR-010 까지는 QMS 가 이벤트를 **보내기만** 했습니다. 받은 쪽이 실제로 처리했는지, 실패했는지, 어떤 작업 지시·전표 번호가 생겼는지 QMS 는 몰랐습니다. 응답을 받으면 메시징의 세 가지 문제가 함께 생깁니다.

| 문제 | 예 |
|---|---|
| 중복 | 같은 응답이 두 번 도착 (재전송) |
| 순서 뒤바뀜 | "처리 완료"가 먼저 오고 "수신 확인"이 늦게 도착 → 상태가 되돌아가면 안 됨 |
| 실패 | ERP 만 실패 → 다시 보내야 하는데, 이미 처리한 MES 에 같은 업무가 또 생기면 안 됨 |

## 결정 1. 응답은 단계 번호(seq)가 있는 상태 전이
가상 MES/ERP 는 시스템마다 `RECEIVED`(seq 1, 수신 확인) → `PROCESSED`(seq 2, 작업 지시·전표 번호) 또는 `FAILED`(seq 2, 사유)를 응답 토픽 `integration.ncr.ack` 로 보냅니다 (key = 부적합 번호, 같은 부적합의 응답은 같은 파티션).

QMS 의 `usp_ApplyIntegrationAck` 는 이벤트·시스템별 현재 상태(`integration_status`)를 **seq 가 더 클 때만** 바꿉니다. 늦게 온 낮은 단계 응답은 기록만 하고(`applied = 0`) 상태는 그대로 둡니다 → 결과 `STALE`.

## 결정 2. 응답 ID 로 중복 제거, 응답 ID 는 결정적으로
모든 응답은 `integration_ack_log`에 `response_id`(기본 키)로 남고, 같은 ID 가 다시 오면 `DUPLICATE` 로 무시합니다.

가상 MES/ERP 는 `response_id`를 **(이벤트 ID, 시스템, 단계)에서 계산**합니다(UUID v3). 그래서 같은 이벤트를 다시 받으면 업무는 다시 만들지 않고 **같은 응답을 다시 보낼 수 있습니다.** 응답이 중간에 사라져도 이벤트 재전송(아웃박스의 at-least-once)으로 회복되고, QMS 는 중복을 거릅니다. 응답을 보내지 못하면 수신 처리 자체를 실패로 돌려 Kafka 가 이벤트를 다시 전달하게 했습니다.

## 결정 3. 실패하면 화면에서 다시 보내기 — 실패한 시스템에만
가장 최근 이벤트에 `FAILED`가 있으면 화면에 **[실패한 연계 다시 보내기]** 가 나옵니다 (품질 담당자만). 다시 보내기는:
- **새 event_id** 로 보냅니다. 이전 실패 기록은 그대로 남아 이력이 됩니다.
- 이벤트에 `targetSystems`(실패한 시스템 목록)를 담고, 받는 쪽은 그 시스템만 처리합니다. 이미 처리한 시스템에 같은 업무(작업 지시 등)가 두 번 생기지 않습니다.
- 실패가 없는데 다시 보내려 하면 409 로 거절합니다.

| 선택지 | 버린 이유 |
|---|---|
| 같은 event_id 로 다시 보내기 | 받는 쪽이 "이미 받은 이벤트"로 보고 건너뜀 (ADR-010 의 중복 제거와 충돌) |
| 실패 시 자동 재시도 | 시험용 실패처럼 원인이 그대로면 무한 반복. 실제 업무 실패(마스터 데이터 없음 등)는 사람이 원인을 고친 뒤 보내야 함 |

## 시험용 실패 설정
`qg.integration.simulate-failure=ERP` 처럼 지정한 시스템은 실패 응답을 보냅니다. 실패 → 다시 보내기 흐름을 확인하는 데 씁니다 (기본값은 빈 값).

## 결과
- 화면 "MES/ERP 연계": 이벤트마다 시스템별 수신 확인 / 처리 완료 + 번호 / 실패 + 사유, 실패 시 다시 보내기 단추
- `POST /api/qms/ncrs/{ncrNo}/integration/retry`

## 한계
- 응답이 오래 오지 않을 때(시간 초과) 알려 주는 감시는 없습니다. 화면에 "MES/ERP 응답 대기"로만 보입니다.
- 실제 MES/ERP 의 번호 체계·실패 코드는 가상 규칙입니다.
