# ADR-022. 측정으로 정한 기본값 세 가지: 자동 조치 확신도 80, ML 먼저(skip), 분석 방식 tools 유지

- 상태: 채택
- 날짜: 2026-11-25
- 관련: [ADR-016](ADR-016-multi-agent-pipeline.md), 로드맵 E7·A1, [평가 결과](../evaluation.md)

## 배경
11/24 밤 맥에서 v2 프롬프트로 홀드아웃·E7·A1·E3-fast 를 측정했다. 그 결과로 기본값 세 가지를 정했다.
측정값의 근거 파일은 `eval/calibration_report.md`, `eval/ab_prefetch.md`, `eval/results/20261125-*` 이다.

## 결정 1. 자동 조치 확신도 기준: LOW 조치도 80 (기존 50)

| 확신도 (v2 홀드아웃, 127단계) | 원인 적중률 |
|---|---|
| 50~69 | 27% (3/11) |
| 70~79 | 80% (16/20) |
| 80 이상 | 97~100% |

- `ActionPolicy` 는 LOW 조치를 확신도 50 이상이면 자동 실행했다. 홀드아웃에서 50~69 구간의 원인은 4번 중 3번 틀렸다.
- "LOW 조치는 되돌리기 쉬우니 반반 확률도 허용한다"는 이유도 생각했지만, 실제 적중률이 반반보다 낮아 그 설명이 데이터와 맞지 않는다.
- 그래서 LOW·MEDIUM 모두 80 으로 맞췄다(`ActionPolicy.MIN_CONFIDENCE`). 자동 실행은 줄고 승인 대기는 늘어난다.
- 승인 대기가 늘어 생기는 부담은 같은 조치 묶기(PR #104)로 줄인다.

## 결정 2. ML 먼저 판단: 기본 `skip`

- `qg.agent.ml-triage.mode` 를 `skip` 으로 둔다. 11-24 E6 결과 커밋에서 값이 `off` 로 바뀌어 주석·문서와 어긋나 있었다.
- E3-fast 결과: ML 끔은 평균 52.7초, skip 은 27.2초였다. 정답은 둘 다 15/15 였고, LLM 과 비교한 8건은 모두 일치했다.
- 한계: 비교 표본(8건)이 앱 안내 기준(30건)보다 작다. 그래서 건너뛸 수 있는 사건의 10%를 LLM 으로도 분석해 비교하는 표본 점검(`audit-rate: 0.1`)을 유지한다.
- 평가에서 LLM 만의 시간을 잴 때는 `QG_AGENT_ML_TRIAGE_MODE=off` 로 끈다.

## 결정 3. 분석 방식: `tools` 유지 (prefetch 는 비교용)

- A1(5사례 1회)에서 prefetch 는 정답·진단 시점이 같았다. 그러면서 지연은 46%, 입력 토큰은 80%, 비용은 34% 줄었다.
- 그래도 바꾸지 않는다.
  - 표본이 5사례 1회뿐이다.
  - prefetch 는 조사 절차 1~5를 정해진 인자로만 본다. 홀드아웃에서 못 맞힌 체크 링 마모처럼 절차 밖 조사가 필요한 사례에서도 같은 결과가 나올지 모른다.
- 다시 볼 조건: `./scripts/ab_eval.sh prefetch 3` 이나 홀드아웃에서도 정답이 같으면 그때 기본값을 바꾼다.
