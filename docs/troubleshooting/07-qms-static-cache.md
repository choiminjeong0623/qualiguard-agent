# 07. QMS 화면을 고쳤는데 브라우저에 새 기능이 보이지 않음

- 발생일: 2026-11-15 (F-09 MES/ERP 연계 E2E 확인 중)
- 영향: 서버에는 새 코드가 올라갔지만 화면에 "MES/ERP 연계" 영역이 나오지 않아 기능이 없는 것처럼 보임
- 상태: **해결** (정적 파일 응답에 `no-cache`)
- 관련: [ADR-009](../decisions/ADR-009-qms-review-screen.md), [ADR-010](../decisions/ADR-010-ncr-integration-outbox.md)

---

## 1. 현상

F-09를 넣은 뒤 승인 화면 상세에 "MES/ERP 연계" 영역이 보여야 했는데, 브라우저에는 이전 버전 화면이 그대로 나왔습니다.

## 2. 원인

QMS 화면은 jQuery 정적 페이지(`static/qms/index.html`, `qms.js`, `qms.css`)입니다([ADR-009](../decisions/ADR-009-qms-review-screen.md)에서 프런트 빌드를 두지 않기로 결정). 파일 이름에 버전이나 해시가 붙지 않기 때문에, 브라우저가 **이전에 받은 `qms.js`를 캐시에서 그대로 썼습니다.** 서버에는 새 코드가 올라가 있었습니다.

빌드 도구가 있는 프런트엔드는 파일 이름에 해시를 붙여 이 문제를 피하지만, 빌드 없는 정적 페이지를 고른 대신 이 처리를 직접 해야 했습니다.

## 3. 조치

| 조치 | 파일 |
|---|---|
| 정적 리소스 응답에 `Cache-Control: no-cache` (매번 서버에 변경 여부 확인, 바뀌지 않았으면 304로 가볍게 응답) | `application.yml` (`spring.web.resources.cache.cachecontrol.no-cache: true`) |

## 4. 재발 방지

- 화면을 바꾸는 PR의 E2E 확인은 **새 창(또는 캐시 비움) 기준**으로 합니다.
- 화면 파일이 많아지면 파일 이름에 버전을 붙이는 방식(예: `qms.js?v=커밋`)으로 바꿉니다.

## 5. 배운 점

- **"기능이 안 보인다"가 항상 서버 문제는 아니다.** 서버와 화면 중 어느 쪽 문제인지 먼저 나눠 봐야 합니다.
- **기술 선택에는 대가가 따라온다.** 빌드 없는 정적 페이지는 8GB 환경과 라이선스 문제를 피했지만, 빌드 도구가 해 주던 캐시 무효화를 직접 챙겨야 했습니다.
