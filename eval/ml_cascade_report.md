# ML 먼저, 애매하면 LLM — 실험 측정

`./scripts/ml_cascade.sh` 로 다시 만들 수 있습니다 (LLM 없이). 생성: 2026-11-23 08:17. 모델: 랜덤 포레스트 나무 100개, 학습 경보 2851건 (seed 101~130). 앱에 넣은 모델과 같습니다.

> 시뮬레이터 합성 데이터입니다. LLM 을 건너뛴 경보의 정답률은 ML 만의 정답률이고, LLM 으로 넘긴 경보는 기존 에이전트 평가 수치를 따릅니다.

## 규칙

- ML 이 **학습한 고장 원인**(히터 열화·냉각 막힘·체크 링 마모·압력 센서 이상)을 확률 **0.9 이상**으로 고르면 LLM 을 부르지 않습니다. 이때도 같은 조회 도구(SPC 요약·센서 추이·불량 요약)로 실제 수치를 근거로 붙이고, 검증 에이전트와 사람 승인을 그대로 거칩니다.
- **단발성(NOISE)** 은 ML 이 확신해도 LLM 으로 넘깁니다. 학습하지 않은 고장은 '단발성'으로 들어가기 때문입니다 (ml_cause_report.md 3절).
- 확률이 낮으면 LLM 으로 넘깁니다. 검증 에이전트가 되돌리면 두 번째 시도는 LLM 이 합니다.

## 해석

- 학습한 고장이 대부분인 공장이면 LLM 호출이 크게 줄어듭니다 (1절). 줄어드는 만큼 분석 시간(평균 44초 → 수십 ms + 도구 조회)과 Gemini 비용이 줄어듭니다.
- 단발성 경보와 확신이 낮은 경보는 LLM 이 그대로 봅니다. 처음 보는 고장은 대부분 이쪽으로 넘어갑니다 (3절).
- 위험은 '처음 보는 고장을 다른 학습된 고장으로 확신'하는 경우입니다. 기준 확률 0.9 에서 0건, 0.7 에서 0건이었습니다. 이 경우에도 결과는 초안일 뿐이고 사람이 승인하기 전에는 확정되지 않습니다.
- 그래서 앱에서는 **기본 꺼짐**(`qg.agent.ml-triage.mode=off`)으로 두고, 먼저 `shadow`(ML 판단을 기록만, LLM 은 그대로)로 실제 경보에서 일치율을 본 뒤 `skip` 을 켜는 순서를 권합니다.
